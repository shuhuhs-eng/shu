# 「サロンらしさ」設計 Ver2

Beauty Reachのブランドコンセプト「あなたらしさ × サロンらしさ」の、サロン側を担う設計。
**本書は設計文書のみであり、実装コード・SQL・マイグレーションは一切含まない。**

---

## 0. 改訂履歴

Ver1からの主な変更点（4点の指摘を反映）：

1. 美容師の6才能スコアとサロン側の軸を同一尺度として扱わないよう、独立した「CultureAxis」を新設した
2. 回答者（respondent_role / respondent_user_id / answered_at）を必ず保持する構造にした
3. brand（会社・ブランド）／store（店舗）／recruiting（今回の募集）の3層構造に分離した
4. `matchPct()`（コサイン類似度）の単純流用を確定せず、将来のマッチングを4分類（一致・受容・補完・条件）に整理した

---

## 1. 「サロンらしさ」の最終データ構造

### 1.1 美容師の才能スコアとは独立したCultureAxis

美容師のT/S/H/B/A/Mは「本人が持つ才能・傾向」の量。サロン側の軸は「その才能をどれだけ歓迎・活用・育成できる環境か」という組織文化の性質であり、**両者は別の尺度として設計する**。名称も才能軸とは明確に区別する。

各軸には性質の違いがある。「多いほど良い」軸と、「方向性が合っているかどうか」で決まる軸は性質が異なり、これは4節の将来マッチング分類（受容相性／一致相性）にそのまま対応する。

| CultureAxis（コード） | 内容 | 性質 |
|---|---|---|
| `education_support` | 新人・若手をどれだけ手厚く育てる体制か | 度合い型（多い＝受容力が高い） |
| `challenge_openness` | 新しい技術・提案・変化にどれだけ開かれているか | 度合い型（多い＝受容力が高い） |
| `personal_brand_support` | スタッフ個人の発信・指名づくりをどれだけ後押しするか | 度合い型（多い＝受容力が高い） |
| `customer_relationship_style` | 顧客との関係を家族的に築くか、洗練された距離感で築くか | 方向性型（近さで決まる） |
| `team_collaboration_style` | フラットな協働か、役割が明確な組織か | 方向性型（近さで決まる） |
| `management_style` | トップダウンか、権限委譲型か | 方向性型（近さで決まる） |

名称・軸数は今後見直してよい前提とする。既存サロン14問診断のT/S/H/B/A/Mは、参考データとして`salon_culture_profiles`から参照はするが、「サロンらしさ」の正式値そのものではない。**正式値は上記CultureAxisであり、既存診断スコアは補助的な裏付けデータという位置づけに明確化する。**

### 1.2 データ構造（概念）

**`salon_culture_profiles`**（現在の代表値。2節の3層構造・3節の回答者構造と組み合わせて保持）

| 項目 | 内容 |
|---|---|
| 対象範囲 | 2節で定義する3層（brand／store／recruiting）のいずれかを指す |
| CultureAxisの値 | 上記6軸それぞれの値（度合い型は0〜100等の量、方向性型は「どちら寄りか」を表す位置） |
| 文化に関する自由回答 | 5節の質問への回答（層ごとに整理） |
| 価値観の優先順位 | 美容師`value_priorities`と同形式 |
| 参考データへの参照 | サロン14問診断（`diagnosis_results`, mode='salon'）への参照。正式値ではなく補助情報 |
| サロンらしさの要約文 | 将来AIが生成する要約（現時点では空欄で構わない） |

**`salon_culture_history`**（3節で詳述する回答者情報を必ず伴う履歴）

## 2. brand / store / recruiting の3層構造

Beauty Reachは将来、個人サロン・複数店舗サロン・大手チェーンのすべてを扱うため、「会社としての理念」「店舗固有の文化」「今回の募集における事情」を分離する。

```
① brand（会社・ブランド）層
   └ 理念・全社的な価値観。個人サロンでは店舗と実質的に一致してよい
② store（店舗）層
   └ その店舗の日々の実態としての文化。brandを引き継ぎつつ、
     実際にはbrandの理想と多少異なってもよい（本社の理念と現場の実態のズレも
     将来的な分析対象になりうる）
③ recruiting（今回の募集）層
   └ 一時的・時期依存の事情（「今は即戦力が欲しい」等）。storeの文化を
     土台にした、今回の募集限定のレイヤー
```

美容師とのマッチングでは②storeを主として重視する。①brandは店舗の文化が未回答のときの補完・大枠のコンテキストとして、③recruitingは今回の募集における一時的な重み調整として使う、という優先順位にする。

| 層 | 対応する既存/将来の組織単位 | 変化の頻度 |
|---|---|---|
| brand | `requirements-v1.0.md` 5章で設計済みの`salon_organizations`（法人） | 低い（ほぼ固定） |
| store | 同章の`salon_stores`（個別店舗） | 中程度（スタッフ構成の変化等でゆるやかに変わる） |
| recruiting | storeに紐づく「今回の募集」という一時的な文脈（新規概念） | 高い（募集ごとに変わる） |

1店舗の個人サロンの場合、brand層とstore層はほぼ同一の回答で構わない（②を①からコピーする、または②のみ回答してもらい①を省略する運用も許容する）。

## 3. 回答者・確認者の構造

サロンらしさは「誰が答えたか」で意味が変わるため、回答（履歴）ごとに回答者情報を必須で保持する。

| 項目 | 内容 |
|---|---|
| `respondent_role` | `owner_representative`（オーナー・代表者）／`store_manager`（店舗責任者）／`recruiter_hr`（採用担当）／`other`のいずれか |
| `respondent_user_id` | 回答したBeauty Reachアカウントへの参照 |
| `answered_at` | 回答日時 |

**将来拡張（現Phaseでは実装しない）**：「採用担当が入力→オーナーまたは店舗責任者が確認」という承認フローに備え、`confirmation_status`（未確認／確認済み）・`confirmed_by_user_id`・`confirmed_at`に相当する情報を、履歴レコードに後から追加できる形にしておく。今回はこの確認機能自体は作らず、構造上の余地だけを残す。

## 4. 将来のマッチング4分類（計算式・重みは今回決定しない）

コサイン類似度（既存`matchPct()`）を単純流用して「似ているほど良い」と決め打ちしない。相性は性質の異なる4種類に分けて評価できる構造にする。具体的な統合スコア・重み付けはPhase 5で実データを見ながら設計する。

| 分類 | 内容 | 主に参照するデータ |
|---|---|---|
| A. 一致相性 | 価値観・働き方・接客方針など、方向性が近いほど良いもの | 美容師の`value_priorities` × サロンの価値観優先順位／方向性型CultureAxis |
| B. 受容相性 | 美容師の強みを、サロンがどれだけ歓迎・活用できるか（talent × environment） | 美容師の6才能スコア（本人の量）× サロンの度合い型CultureAxis（環境の受容力） |
| C. 補完相性 | 在籍スタッフに不足している強みを補えるか（team complementarity） | 将来の`salon_staff_composition`との差分 |
| D. 条件適合 | 勤務地・給与・休日・雇用形態等、客観的な条件の一致 | 既存の希望条件系フィールド（`stylist_profiles`の希望勤務地・希望年収帯等、`salon_stores`の募集条件） |

A・Bが「らしさ」同士の相性、Cが組織としての穴埋め視点、Dが純粋な条件マッチングという棲み分けであり、この4つは合算前の別々の評価軸として保持し、統合ロジックはPhase 5に委ねる。

## 5. サロン側の質問案（3層構造に対応）

### 5.1 brand層（会社・ブランドとして。owner_representativeが回答する想定）

| # | 質問 | 対応するCultureAxis |
|---|---|---|
| B1 | 会社として、美容師にどう育ってほしいか | education_support |
| B2 | 会社として大切にしたい価値観トップ3は（候補から選択） | 価値観 |

### 5.2 store層（店舗の日々の実態として。store_managerまたはrecruiter_hrが回答する想定）

| # | 質問 | 対応するCultureAxis |
|---|---|---|
| S1 | 新人がミスをしたとき、店として最初にすることは | education_support |
| S2 | お客様との関係で、一番大切にしていることは | customer_relationship_style |
| S3 | チームで一番大事にしている瞬間は | team_collaboration_style |
| S4 | 最近、サロンとして変えたこと・挑戦したことは | challenge_openness |
| S5 | SNSやブランディングについて、サロンとしての考え方は | personal_brand_support |
| S6 | 店長として、スタッフとどう関わりたいか | management_style |
| S7 | 店舗として大切にしたい価値観トップ3は（候補から選択、brandと異なってもよい） | 価値観 |

### 5.3 recruiting層（今回の募集について。recruiter_hrまたはstore_managerが回答する想定）

| # | 質問 | 用途 |
|---|---|---|
| R1 | 今回の募集で、特に大切にしたい経験・強みは | Bの受容相性評価に一時的な重みを与える |
| R2 | 今、チームに足りていないと感じる強みは | Cの補完相性評価の直接的な入力情報 |
| R3 | 今回に限り、特別に重視したい条件はあるか | Dの条件適合の一時的な補足 |
