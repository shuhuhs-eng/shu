# 0070・0071 ローカル検証一式（README）

**本番では実行しません。** 検証は使い捨てのローカルDBだけを作って消します。本番に流すのは、SQL本体・巻き戻し・停止・再開・適用前後チェックの `.sql` だけです。

## 前提（満たさない場合は、DBを触る前に明確なエラー・終了コード2で止まります）
- PostgreSQL 15 以上のローカルサーバーに、スーパーユーザーで `psql` 接続できること
  - 例: `su postgres -c "bash run_all_0070_0071.sh"`（または `PGHOST` / `PGUSER` / `PGPASSWORD` を設定）
- 既存migration 0001〜0061（同梱の `migrations/`、リポジトリの `supabase/migrations`、または環境変数 `MIGRATIONS_DIR`）
  - もしくは同等のテンプレートDB（環境変数 `TEMPLATE_DB`。0061までのスキーマ＋Supabase互換スタブ）
- 0058本体 `0058_diagnosis_change_limits.draft.sql`（同じディレクトリ）
- ロール（anon / authenticated / service_role など）と auth・storage スキーマのスタブは `stub_supabase.sql` が作ります（テンプレートDB作成時）

## DBの扱い
- 作る・消すのは、名前が `vfy_` で始まり、かつ検証用の印（DBコメント）が付いたDBだけです。印のないDBは、同名があっても削除せず止まります。
- テンプレートDB（既定 `vfy_tpl_0061`）は初回だけ自動作成し、再利用します（`VFY_TEMPLATE_NAME` で名前変更可）。

## 適用順と巻き戻しの順序（SQL本体の運用）
- 適用順は **0058（適用済み）→ 0070 → 0071** で固定です。0071は、0070が無いと冒頭のチェックで中止します。
- 巻き戻しは逆順: **0071 → 0070**。0071適用済みのまま0070を巻き戻そうとすると中止します。
- どの巻き戻しも、中止判定より前に対象表をロック（待ち上限15秒。取れなければ何も変更せず中止）し、確認から削除・復元まで同じトランザクションで保護します。
- 年齢の扱い（確定方針）: 生年月日は必須登録（満15〜100歳）。既存会員は推測せず、登録と表示方法（実年齢／年代）の選択が済むまでサロン向け一覧・画像・スカウト送信先から保留。公開判定は正確な満年齢（満18歳未満はフラグ `minor_salon_public` が保留のあいだ出さない）。サロン（店舗単位）は年代表示の美容師に実年齢の開示を依頼でき、本人が承認した店舗にだけ現在の満年齢が出る。詳細は `0070_age_policy.md`。以前の「未登録は従来どおり表示」は撤回。
