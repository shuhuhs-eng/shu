# 経験年数（空欄・0年）の扱い: 調査と修正案

作成: 2026-11-15。**調査と案のみ。コード・DB・既存会員の値は変更していません。** DB変更（migration）は不要です。

## 1. 結論（要約）
- **DBは区別できています**: 列 `stylist_profiles.experience_years` は NULL 可（0〜60）。保存関数に NULL を渡すと NULL、0 を渡すと 0 で保存されます（ローカル検証 `experience_years_verify.sh`、5件PASS）。
- **問題はアプリの入力検査**: `lib/validation/profile.ts` が `z.coerce.number()` のため、**空欄・空白・null が 0 に変換**されます（実測: `""`→0、`" "`→0、`null`→0）。現在は画面の必須チェックで空欄が通らないため表面化していませんが、検査そのものが「未登録」を表せません。学生・新卒は実績が無いので、経験年数を空にできる必要があります。
- **マッチング計算には使われていません**: SQLの `calculate_match_axes` と相性・診断の計算は `experience_years` を参照しません（診断の「経験」は診断の回答から取る別の値）。NULLにしても相性・診断の結果は変わりません。
- **表示側は、ほぼ NULL に対応済み**（NULLなら非表示、または「未設定」）。ただし「0年」と「未登録」の文言の統一は未対応。

## 2. 使われている場所（影響範囲）
| 区分 | 場所 | 現状 |

## 3. 既存会員の値について
- 既存の値は**推測で変更しません**。0 が「本当に0年」なのか「空欄が0になった」のかは、保存済みの値からは区別できません。
- 現状の分布は、読み取り専用の `experience_years_readonly.sql`（件数のみ・個人が特定できる値は出ない）で確認できます（**本番の件数は未確認**）。
- 0 の人は、そのまま「経験0年」と表示されます（変更しない）。本人が編集して空欄に直した場合だけ NULL になります。

## 4. 修正案（アプリのみ。承認後に実装）
**A（推奨）**
1. 入力検査: 空欄・空白・null は **NULL（未登録）**、`"0"` は 0、非数・小数・範囲外（0〜60以外）はエラー。0 へは変換しない。
2. 入力欄: ラベルを「美容師経験年数（任意）」にし、HTMLの required を外す。登録ウィザードの「入力してください」も外す。経験者にも任意にするので、サロン側の情報が減る可能性がある（下の B と比較）。
3. 表示の統一: 共通の整形関数 `formatExperience(years)` を作り、NULL→「経験 未登録」（サロン向けの一覧では非表示も選べる）、0→「経験 0年」、n→「経験 n年」。上の表の各画面を同じ関数に置き換える。
4. テスト: 検査（空欄→NULL・0→0・不正値はエラー）、整形関数、保存関数への引数（NULL/0）、各画面の表示。
5. 既存会員の値は触らない。DB変更なし。0070の保存関数（v2・旧）の引数はそのまま（NULLは元から受け付ける）。

**B（区分に応じて必須を切り替える）**
- 経験者・未設定の人は必須のまま、学生・新卒（0071適用後）の人だけ任意にする。経験者の入力情報を減らさない一方、区分の読み取りが保存画面で必要になり、0071未適用では必須のまま、という分岐が増える。実装は A より大きい。

**推奨と理由**: A。DB変更がなく、0070の保存経路・マッチングに影響せず、区分に依存しないため、0071の適用前後で挙動が変わらない。サロン向けに経験年数を出したい場合は、プロフィールの公開条件ではなく表示の工夫（任意項目の案内文）で補う。

## 5. 決めていただくこと
- A か B か（推奨は A）。
- サロン向けの一覧で、NULLを「経験 未登録」と出すか、非表示のままにするか。
