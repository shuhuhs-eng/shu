# 0061 本番適用の手順（記録用。適用は人が行う）

対象は `supabase/migrations/0061_admin_operations.sql` のみ。0058・0059・0062〜0064は含まない。
Claudeは本番に接続・適用しない。前提: 0060が適用済み。

## 手順
1. **適用前チェック** `0061_preapply_check.sql` を実行。
   - 全行 PASS（最後の行は INFO）。FAIL があれば本体を適用せず、FAIL 行を共有して確認する。
   - **INFO のハッシュ（本番で出た値）を控える。** 資料内の e789ba7b… はローカルの値で、本番の期待値ではない。
2. **本体** `supabase/migrations/0061_admin_operations.sql` を適用（begin〜commit 1回。エラー時は自動ロールバック）。
3. **適用後チェック** `0061_postapply_check.sql` を実行。
   - FAIL 0。INFO のハッシュが手順1で控えた本番の値と一致（既存オブジェクトに変化なし）。
4. 確認後に、依存アプリをpush・デプロイ（それまで保留）。
5. 運営・サロン・美容師のアカウントで、連絡の作成・受信・返信を確認。実際の通知メール送信は含めない（送信設定と送信先を確認後、別途）。

## 問題があった場合
- 未使用（0061の8表が全て0行）: `0061_rollback_unused.sql`。実行後に適用前チェックを再実行し、手順1の本番ハッシュと一致を確認。
- 運用開始後（データあり）: DROP しない。書き出し後に `0061_suspend_keep_data.sql`（停止）、`0061_resume.sql`（再開）。詳細は `0061_RECOVERY.md`。

## 確認できていないこと
本番での実行結果、本番の既定権限、実アプリ経由・実アカウントでの動作。

## 適用前の基準ハッシュが無い場合の代替（本番の現在状態・読み取り専用）
適用前チェックのハッシュを再提示できない場合は、「一致確認済み」と記録しない。代わりに `0061_prod_readonly_check.sql`（1つのSELECTのみ・書き込みなし）を本番で実行する。
- 確認できること: 0061の8表・17関数が、migrationから計算した定義の値と一致／RLS・ポリシー無し・権限（anon・service_role・PUBLICに付与なし）／トリガー有効／行数。VERDICT が OK（FAIL 0）であること。
- 確認できないこと: 0061が既存オブジェクトに影響していないこと（適用前の基準が無いため）。migrationの文は新規8表・その索引・RLS・権限・新関数だけで、既存オブジェクトを変更する文は無い（静的確認）。項目6のハッシュは今回あらためて取る基準で、適用前との一致ではない。
