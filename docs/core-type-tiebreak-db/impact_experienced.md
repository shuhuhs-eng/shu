# 経験者版：丸め・同点の修正で、今後の判定が変わるケース（変更前後）

経験者版の質問・配点・6軸の計算は変えていない。変わるのは、6軸の点数から8タイプの1位・2位を決める最後の段階の2点だけ。**保存済みの履歴・初回確定タイプは変更しない**（0078は関数だけを差し替え、既存の行は書き換えない。検証済み）。

## 調べ方
- 実際の経験者の質問 Q（30問）に、各問を一様に選ぶ回答を 300,000 通り作り（固定シード）、6軸の点数にした（重複を除くと 289,727 通り）。
- 変更前のアプリ（コミット 56f9814 の calculateCoreType の写し）、変更後のアプリ、変更前のDB関数（0004）、変更後のDB関数（0078）を、同じ6軸の点数で比べた。DBはローカルの使い捨てDBで、本番へは接続していない。
- 回答は一様乱数であり、実際の利用者の分布ではない。割合は「起こりやすさの目安」で、実データの割合ではない。

## 影響の整理
- 画面（登録前のプレビュー）と、登録後に保存される結果は、変更前は A・B の分だけ食い違うことがあった。変更後は一致する（D=0）。
- 回答が変わらないのに結果が変わりうるのは、**今後の保存**と**画面のプレビュー**だけ。過去に保存した履歴・初回確定タイプ・変更回数・ロックには触れない。
- 同点・丸め境界での1位・2位は、もともと「僅差」であり、どちらが上かは確信度を持たない。順序の規則（定義順）を揃えただけで、優劣の根拠を足したものではない。
