## 3. 巻き戻し・提供停止の方法（保留回答を失わない）
### 3-1. 入口のスイッチ（コードを戻さない）
環境変数 `NEWGRAD_ENTRY_ENABLED` は**既定で無効**。`true` / `1` / `on` を明示したときだけ新卒入口が有効になる。未設定・空・その他の値は無効。
- 無効のとき止まるもの: 診断1問目の5つ目の選択肢（画面は4択）と、**新卒の新規送信**（サーバーが `newgrad_disabled` で拒否）。
- 無効でも続くもの: 保存済みの新卒結果の表示、保留済みの新卒回答の引き継ぎ（claim）、経験者版の診断。
- 確認: 自動テスト（無効時に新卒送信は拒否、経験者は通常、保留データはclaimできる）、実ブラウザ（有効時の画面）。無効時の画面（4択）は自動テストのみ・実ブラウザは**未確認**。

### 3-2. 公開の順序（確定した運用）
1. 0078 の適用前チェック → 適用 → 適用後チェック（DB）。
2. 新卒入口を**無効のまま**アプリを配備（環境変数を設定しない）。経験者の挙動は変わらず、新卒の取り込み・表示の準備だけが入る。
3. 別途承認後に `NEWGRAD_ENTRY_ENABLED=true` で再配備して入口を出す。
4. 問題が出たら環境変数を外して再配備（入口だけ閉じる）。段階2より前のコードへは戻さない。
5. 0075 は保留のまま。

### 3-3. やむを得ずコードを旧版へ戻す場合
新卒の保留データ・結果が存在する間は、旧コミットへの単純な revert は**行わない**。戻すなら、少なくとも次を含む互換版にする（本変更から入口UIだけを外したもの）。
- `lib/diagnosis-handoff/claim.ts` の版別検証と失敗分類（Cookieを捨てるのは、期限切れ・他者の取得・完了済みがRPCの例外メッセージで明確なときと、既知の版で回答が破損しているときだけ。PGRST202・42883・42501・一般的なP0001・HTTP 4xx・版不明では保つ）
- マイページの新卒分岐（新卒結果に才能・能力・年収の表示を出さない）
- `lib/diagnosis/{newgrad,versioned}.ts` と質問データ
この互換版を作るのは、入口スイッチを使うより手間が大きい。まず 3-1 を使うこと。

## 4. DB（0078）との関係
0078（同点の順序）は新卒版とは独立。新卒版のためのDB変更は**不要**（`diagnosis_version` は自由な文字列、`market_value`・`salary_band` はnull可、現在の診断の `bank` は従来どおり `experienced`、変更判定は「`bank<>'experienced'` または回答が違う」で、15問→30問は変更として数える）。0078を適用しなくても新卒版は動く（同点時のDBの順序が定義順にならないだけ）。

## 5. 保留データの期限・後始末（既存仕様の確認）
- `start_pending_diagnosis_claim` は `claimed_by` / `claimed_at` / `claim_status` だけを更新し、**`expires_at` は延長しない**（コード読み取り・疑似環境でも期限不変を確認）。
- 期限切れの行は、既存の掃除（`cleanup_expired_pending_diagnoses`、Cron）が削除する。期限切れ等がRPCのメッセージ（pending diagnosis not found, claimed by someone else, already completed, or expired）で明確なときだけCookieを消す。一時的な失敗ではCookieを保ち、障害解消後に同じ回答が重複なく取り込まれることをテストで確認。
- 既存の挙動の注記: 同一ユーザーによる PROCESSING の再開は、期限（`expires_at`）を見ない（既存SQLのまま。今回は変更していない）。
