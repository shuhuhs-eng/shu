## 4. Vercelでの有効化手順（本番）
前提: 今回の修正が本番に配備済みで、入口は無効のままであること。経験者のDB確認（3の1）が済んでいること。`NEWGRAD_ENTRY_ENABLED` は**サーバー側**で毎回読まれる（診断ページは都度生成）が、Vercelでは環境変数の変更は**新しいデプロイから**有効になる。
1. Vercel → 本番のプロジェクト → **Settings → Environment Variables**。
2. **Add New**: Key=`NEWGRAD_ENTRY_ENABLED`、Value=`true`。Environment は **Production だけ**にチェック（Preview・Development は外す）。**Save**。
3. **Deployments** → 最新の Production のデプロイの「…」→ **Redeploy**（Production に再デプロイ）。完了（Ready）を待つ。
4. 確認（本番、シークレットウィンドウ）: `/stylist/diagnosis` の1問目が**5択**になる。経験者の選択肢で最後まで回答でき、結果が出て、登録・引き継ぎができる（経験者の従来の動作が変わらないこと）。新卒を選ぶと2問目から新卒向けの質問に変わる。
5. 有効化後の監視: Vercelのログで、`claimDiagnosis.startRecoverable`・`newgrad_disabled`・5xx を確認。DBは 3 の 5 のSQLで、新卒の件数と、保留データの未完了が溜まっていないかを見る。
6. **戻し方（入口だけ閉じる）**: Settings → Environment Variables で `NEWGRAD_ENTRY_ENABLED` を削除（または `false`）→ Redeploy。保存済みの新卒の結果の表示と、保留済み新卒回答の引き継ぎは続く。開いたままの画面から新卒が送られると、専用の案内が出る。コードを古い版へ戻さない。

一般公開は、3 の条件（1〜4の確認、5の記録）を行ってから。条件が揃うまでは、本番は無効のままにする。
